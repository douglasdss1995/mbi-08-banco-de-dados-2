## `01_ddl.sql`

```sql
-- Oficina Mecânica · estrutura do banco (aula 3)
-- Pode ser executado quantas vezes quiser: apaga e recria as tabelas.

DROP TABLE IF EXISTS item_servico;
DROP TABLE IF EXISTS ordem_servico;
DROP TABLE IF EXISTS veiculo;
DROP TABLE IF EXISTS servico;
DROP TABLE IF EXISTS mecanico;
DROP TABLE IF EXISTS modelo;
DROP TABLE IF EXISTS cliente;

CREATE TABLE cliente (
    cod_cliente integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nome        varchar(100) NOT NULL,
    telefone    varchar(20)
);

CREATE TABLE modelo (
    cod_modelo integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nome       varchar(50) NOT NULL,
    marca      varchar(50) NOT NULL
);

CREATE TABLE veiculo (
    placa       char(7) PRIMARY KEY,
    cod_modelo  integer NOT NULL REFERENCES modelo (cod_modelo),
    cod_cliente integer NOT NULL REFERENCES cliente (cod_cliente)
);

CREATE TABLE mecanico (
    cod_mecanico  integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nome          varchar(100) NOT NULL,
    especialidade varchar(50)
);

CREATE TABLE servico (
    cod_servico integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    descricao   varchar(100) NOT NULL,
    valor       numeric(10,2) NOT NULL
);

CREATE TABLE ordem_servico (
    numero       integer PRIMARY KEY,
    data         date NOT NULL DEFAULT CURRENT_DATE,
    placa        char(7) NOT NULL REFERENCES veiculo (placa),
    cod_mecanico integer NOT NULL REFERENCES mecanico (cod_mecanico)
);

CREATE TABLE item_servico (
    numero        integer NOT NULL REFERENCES ordem_servico (numero),
    cod_servico   integer NOT NULL REFERENCES servico (cod_servico),
    valor_cobrado numeric(10,2) NOT NULL,
    PRIMARY KEY (numero, cod_servico)
);

-- Alterações da parte A do exercício
ALTER TABLE cliente       ADD COLUMN email varchar(100);
ALTER TABLE ordem_servico ADD COLUMN observacao text;
ALTER TABLE mecanico      ADD COLUMN ativo boolean NOT NULL DEFAULT true;
```

Pontos de atenção:

- **A ordem do `DROP`** é a inversa da criação: `item_servico` primeiro e `cliente` por último. Quem inverte recebe um erro de
  dependência, e a mensagem ensina a ordem.
- `GENERATED ALWAYS AS IDENTITY` é o modo atual do PostgreSQL; aceitar `serial` (modo antigo) e `GENERATED BY DEFAULT`.
- `data` como nome de coluna é aceito no PostgreSQL. Aceitar `data_os` se o aluno preferir evitar a palavra.
- `char(7)` para a placa é uma escolha; aceitar `varchar(7)`.
- O `ALTER TABLE ... ADD COLUMN ativo boolean NOT NULL DEFAULT true` funciona mesmo com linhas existentes por causa do
  `DEFAULT`. Sem o padrão, falharia em uma tabela com dados: bom ponto de discussão.

Pontos de atenção:

- Os códigos gerados (`cod_cliente`, `cod_modelo`...) começam em 1 em um banco recém-criado. Os `INSERT` seguintes
  referenciam esses números; se o aluno recriar o banco sem reiniciar, os números podem mudar.
- A coluna de identidade **não** é informada no `INSERT`. Se o aluno tentar, o erro é
  `cannot insert a non-DEFAULT value into column "cod_cliente"` (detalhe: a coluna é de identidade `GENERATED ALWAYS`).
- Inserção em várias linhas (`VALUES (...), (...)`) é mais curta, mas aceitar um `INSERT` por linha.

## `03_dml.sql` (B.2, B.3 e B.4)

```sql
-- Conferir antes e depois
SELECT cod_servico, descricao, valor FROM servico WHERE descricao = 'Troca de óleo';
UPDATE servico SET valor = valor * 1.10 WHERE descricao = 'Troca de óleo';
SELECT cod_servico, descricao, valor FROM servico WHERE descricao = 'Troca de óleo';

UPDATE cliente SET telefone = '(47) 98888-0000' WHERE nome = 'Ana Souza';
SELECT nome, telefone FROM cliente WHERE nome = 'Ana Souza';

-- Apagar uma OS: primeiro os itens, depois a ordem
DELETE FROM item_servico  WHERE numero = 1004;
DELETE FROM ordem_servico WHERE numero = 1004;
SELECT count(*) AS ordens FROM ordem_servico;

-- Os três erros de propósito
\echo '--- erro 1: veiculo com cliente inexistente'
INSERT INTO veiculo (placa, cod_modelo, cod_cliente) VALUES ('AAA0A00', 1, 999);
\echo '--- erro 2: apagar cliente que tem veiculo'
DELETE FROM cliente WHERE cod_cliente = 1;
\echo '--- erro 3: cliente sem nome'
INSERT INTO cliente (nome, telefone) VALUES (NULL, '(47) 90000-0000');
```

### Mensagens esperadas (B.4)

As mensagens podem aparecer em inglês ou em português, conforme a instalação do PostgreSQL.

| Erro | Mensagem (resumo) | Por que o banco recusou |
|---|---|---|
| 1 · Veículo com cliente inexistente | `insert or update on table "veiculo" violates foreign key constraint "veiculo_cod_cliente_fkey"` | A chave estrangeira exige que o `cod_cliente` exista em `cliente` |
| 2 · Apagar cliente com veículo | `update or delete on table "cliente" violates foreign key constraint ... on table "veiculo"` | Ainda há veículos que referenciam o cliente: apagar deixaria linhas órfãs |
| 3 · Cliente sem nome | `null value in column "nome" of relation "cliente" violates not-null constraint` | A coluna é `NOT NULL` |

O erro 2 abre o gancho para a aula 8 (`ON DELETE`): hoje o banco **recusa**; lá o aluno escolhe entre recusar, apagar em
cascata ou anular.

## Erros comuns

- Criar `item_servico` antes de `ordem_servico` (a chave estrangeira não encontra a tabela).
- `UPDATE` ou `DELETE` **sem `WHERE`** (altera ou apaga todas as linhas): não aceitar; é o erro mais caro do curso e a aula 6
  trata do uso seguro.
- Chave primária só em `numero` no `item_servico`: perde a composta e impede uma OS de ter dois serviços.
- Guardar `total` na ordem de serviço (contra o modelo: o total é calculado).
- Valores monetários em `float` ou `real`.
