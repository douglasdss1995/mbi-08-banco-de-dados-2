# Sequências (*sequences*): o contador do banco

Leitura de apoio da aula 3. Toda coluna `GENERATED ALWAYS AS IDENTITY` (e todo `serial`) funciona com uma **sequência**.
Entender a sequência explica a numeração automática, os "buracos" nos códigos e o que fazer quando a contagem sai do
lugar. Veja também [`referencia-identity-x-serial.md`](referencia-identity-x-serial.md).

## O que é

Uma sequência é um **objeto do banco que só sabe contar**. Cada vez que alguém pede, ela entrega o próximo número. Ela não
é uma tabela e não guarda linhas: guarda o último número entregue e as regras de contagem (onde começa, de quanto em quanto
anda, onde para).

A analogia é a máquina de senhas de um banco ou de uma farmácia: quem puxa a senha recebe o próximo número, e o número
**nunca volta**, mesmo que a pessoa vá embora sem ser atendida.

## Como o banco usa a sequência

Ao criar a tabela com `IDENTITY`, o PostgreSQL cria a sequência junto, chamada `<tabela>_<coluna>_seq`, e usa o seu
próximo valor sempre que o `INSERT` não informa a coluna:

```sql
CREATE TABLE a (id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY, nome text);

SELECT pg_get_serial_sequence('a', 'id');   -- public.a_id_seq
```

Para listar as sequências do banco, use `\ds` no `psql`, ou:

```sql
SELECT sequencename, start_value, increment_by, last_value
FROM pg_sequences
WHERE schemaname = 'public';
```

## Criar uma sequência própria

Você pode criar uma sequência que **não** está ligada a nenhuma coluna, por exemplo, para numerar pedidos a partir de 1000,
de 5 em 5:

```sql
CREATE SEQUENCE pedido_num START 1000 INCREMENT 5;
```

| Opção | O que faz | Padrão |
|---|---|---|
| `START` | Primeiro número entregue | 1 |
| `INCREMENT` | Quanto soma a cada pedido (pode ser negativo) | 1 |
| `MINVALUE` e `MAXVALUE` | Menor e maior valor permitidos | Os limites do tipo |
| `CYCLE` | Volta ao início ao chegar no fim | `NO CYCLE` (dá erro) |

## As funções da sequência

| Função | O que faz |
|---|---|
| `nextval('seq')` | Avança e entrega o próximo número |
| `currval('seq')` | Mostra o último número que **esta sessão** recebeu (só depois de um `nextval`) |
| `setval('seq', n)` | Define o valor atual; o próximo `nextval` entrega `n + 1` |

```sql
SELECT nextval('pedido_num'), nextval('pedido_num'), currval('pedido_num');
-- 1000, 1005, 1005

SELECT setval('pedido_num', 2000);
SELECT nextval('pedido_num');
-- 2005
```

Dá para usar a sequência como valor padrão de uma coluna comum:

```sql
CREATE TABLE pedido (
    numero  integer PRIMARY KEY DEFAULT nextval('pedido_num'),
    total   numeric(10,2) NOT NULL
);
```

## O que a sequência **não** garante

### Ela não volta atrás

`nextval` não participa da transação. Se você desfaz o `INSERT` com `ROLLBACK`, o número consumido **não é devolvido**:

```sql
INSERT INTO a (nome) VALUES ('x'), ('y'), ('z');     -- ids 1, 2 e 3
BEGIN;
INSERT INTO a (nome) VALUES ('desfeito');             -- consumiu o 4
ROLLBACK;
INSERT INTO a (nome) VALUES ('depois');               -- recebe o 5
```

Resultado: os códigos são 1, 2, 3 e 5. O mesmo acontece se um `INSERT` falhar por erro (violou `CHECK`, `UNIQUE`...).
Os buracos são o preço de duas pessoas poderem inserir **ao mesmo tempo** sem uma esperar a outra: a sequência entrega o
número na hora e não espera o `COMMIT`.

**Regra prática:** o código serve para **identificar** a linha. Se o negócio exige numeração **sem buracos** (por exemplo,
número de nota fiscal), a sequência sozinha não resolve: precisa de uma regra própria, com travamento (a aula 11 mostra
o `FOR UPDATE`).

### Ela não confere o que já existe na tabela

A sequência não olha a tabela. Se alguém grava um código à mão (permitido em `serial` e em `GENERATED BY DEFAULT`, ou com
`OVERRIDING SYSTEM VALUE`), a sequência não percebe, e mais adiante entrega o mesmo número:

```text
ERROR:  duplicate key value violates unique constraint "s_pkey"
DETALHE:  Key (id)=(2) already exists.
```

A correção é colocar a sequência depois do maior código existente:

```sql
SELECT setval(pg_get_serial_sequence('a', 'id'), (SELECT max(id) FROM a));
```

Isso também vale depois de **carregar dados com código já definido**: ajuste a sequência antes de voltar a inserir
normalmente.

### Ela tem fim

Sem `CYCLE`, ao passar do `MAXVALUE` a sequência dá erro:

```sql
CREATE SEQUENCE fim MAXVALUE 2;
SELECT nextval('fim'), nextval('fim'), nextval('fim');
```

```text
ERROR:  nextval: reached maximum value of sequence "fim" (2)
```

Com `CYCLE`, ela recomeça (1, 2, 3, 1...), o que repetiria códigos e é raro para chave primária. Para uma coluna `integer`,
o limite é cerca de 2,1 bilhões; para mais que isso, `bigint`.

## Reiniciar a contagem

Para voltar uma coluna `IDENTITY` ao início (por exemplo, depois de apagar os dados de teste):

```sql
ALTER TABLE a ALTER COLUMN id RESTART WITH 1;
```

Para uma sequência solta: `ALTER SEQUENCE pedido_num RESTART WITH 1000;`. Se a tabela ainda tiver linhas com esses números,
a chave primária vai recusar as repetidas.

Atenção: `TRUNCATE TABLE a;` **não** reinicia a contagem, a não ser que você escreva `TRUNCATE TABLE a RESTART IDENTITY;`.
No curso, o jeito mais simples de recomeçar do zero é rodar o `DROP TABLE IF EXISTS` do início do `01_ddl.sql`.

## Quando usar uma sequência própria

Na maioria dos casos, **não precisa**: o `IDENTITY` já cuida da chave primária. Uma sequência própria faz sentido quando:

- o número é **compartilhado** por mais de uma tabela (um código único para cliente e fornecedor, por exemplo);
- o número tem **regra de formato**, como pedidos a partir de 1000 ou de 5 em 5;
- a numeração é usada em **uma função ou procedure** e não em uma coluna.

## Resumo

- Sequência é um contador do banco: `nextval` entrega o próximo número, e ele nunca volta.
- `IDENTITY` e `serial` são jeitos de ligar uma sequência a uma coluna.
- Os buracos na numeração são normais; o código identifica a linha, não conta linhas.
- Depois de gravar códigos à mão, ajuste a sequência com `setval`.
- Para recomeçar uma tabela de teste, use `RESTART WITH` ou rode o script do zero.
