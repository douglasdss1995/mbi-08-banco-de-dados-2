# Exercício — Modelo v2 e dicionário de dados simples

Banco de Dados 2 · Turma MBI-08 · Aula 5

|                   |                                                                                                     |
| ----------------- | --------------------------------------------------------------------------------------------------- |
| **Individual**    | Cada aluno entrega o seu                                                                            |
| **Como entregar** | Uma atividade no Google Classroom, com o MER (imagem ou PDF) e o dicionário de dados simples em `.md` |
| **Prazo**         | Sem horário limite por dia. O ideal é entregar até o fim da aula 5. Vale entregar até 18/11         |
| **Nota**          | De 0 a 10 (pontos indicados em cada item)                                                           |
| **IA**            | Liberada. Anote no fim da entrega qual IA usou e para quê, e saiba explicar tudo o que entregou     |
| **Colaboração**   | Pode trocar ideias com colegas, do mesmo tema ou não. Anote **com quem conversou** e sobre o quê    |

Na aula 4 você leu o relato do cliente do seu projeto e desenhou o modelo. Hoje você apresentou (ou assistiu) e viu os erros e
acertos da turma. Agora entregue a **versão corrigida** do seu modelo (a v2) e o **dicionário de dados simples** dele.

Siglas: **MER** (Modelo Entidade-Relacionamento), **PK** (*Primary Key*, chave primária), **FK** (*Foreign Key*, chave
estrangeira), **N:N** (muitos para muitos).

## O que entregar

### Parte A — MER corrigido (3 pontos)

O MER com **todas as tabelas**, as **PK** e as **FK** marcadas e as ligações (1:N e N:N) bem desenhadas. Pode ser feito no
ERD Concepts (*Entity Relationship Diagram*, diagrama entidade-relacionamento) ou à mão; entregue como imagem ou PDF.

### Parte B — Dicionário de dados simples (4 pontos)

Preencha o [dicionário de dados simples](dicionario-de-dados-simples.md) de cada tabela do seu modelo, num arquivo `.md`.
Para cada tabela: o nome e para que serve. Para cada campo: o nome e a explicação.

Mínimo: **as tabelas principais** do seu projeto (6 a 8). Se o seu modelo tiver menos, explique por que.

### Parte C — Decisões e correção (3 pontos)

Em um arquivo `decisoes.md`:

1. **Três decisões** que você tomou e por quê (ex.: «o preço muda, então fica numa tabela de histórico»).
2. **O que a turma corrigiu** no seu modelo: pelo menos duas mudanças entre a v1 e a v2.
3. **Uma dúvida** que ainda ficou, para o professor.

## Como a nota é dada

| Item | Pontos |
|---|---|
| MER completo e legível | 3 |
| Dicionário: tabelas e campos bem explicados | 4 |
| Decisões e mudanças explicadas | 3 |

## Para conferir antes de entregar

Passe o [checklist de modelagem](checklist-de-modelagem.md) pelo seu modelo. Se algum item ficar sem marcar, explique no
`decisoes.md` ou corrija.
